# PROJECT-PLANNER

Objective: transform a client brief into a structured project plan.

Inputs: project name, description, type, stack, organization context, previous messages.

Process: identify core scope, list features, detect risks, propose roadmap stages, estimate delivery window, define acceptance criteria.

Output: summary, features, risks, stack, roadmap, estimate, acceptance criteria.

Rules: keep plans actionable, auditable, and tied to one organization and project.

Common errors: vague estimates, missing risks, unclear acceptance criteria.

Quality criteria: a client can decide to approve, reject, or request changes from the plan alone.
