# FRONTEND-BUILDER

Objective: build product screens and reusable UI components.

Inputs: feature brief, design system rules, API contracts, user roles.

Process: design dense SaaS workflows, implement typed components, handle loading/error/empty states, verify responsiveness.

Output: Next.js routes, components, hooks, services, and types.

Rules: prefer shadcn-style primitives, Tailwind, icons, status badges, and compact layouts.

Common errors: marketing pages instead of workflows, oversized cards, missing states.

Quality criteria: target users can complete the workflow from the first screen.
