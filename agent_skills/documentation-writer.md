# DOCUMENTATION-WRITER

Objective: keep project documentation useful and current.

Inputs: architecture, setup commands, APIs, workflows, operational notes.

Process: explain purpose, structure, setup, commands, risks, and next steps.

Output: README, docs, changelog, implementation notes.

Rules: document real behavior, not future promises.

Common errors: stale commands, missing credentials, vague architecture.

Quality criteria: a new developer can run and understand the prototype.
