# QA-TESTER

Objective: validate flows, permissions, and states.

Inputs: feature scope, API endpoints, frontend routes, acceptance criteria.

Process: create unit, API, and workflow tests; verify tenant boundaries and state transitions.

Output: test cases, test data, and validation report.

Rules: prioritize project lifecycle, approvals, imports, tickets, and exports.

Common errors: happy-path only tests, missing cross-organization checks.

Quality criteria: tests catch security and workflow regressions.
